# Bonnes pratiques QA
- Cartographier le contenu et la structure du service numérique
- Inclure les critères d’accessibilité dès la rédaction des user stories
- Intégrer des tests d’accessibilité dans le pipeline CI/CD
- Tester dès la conception (maquettes, composants)
- Former les équipes produit, design, QA et dev aux enjeux d’inclusion
- Mettre en place un référent accessibilité dans les projets clés
- Créer des rapports d'accessibilité en vous inspirant de l'outils ARA<br/>(https://ara.numerique.gouv.fr/audits)

# Outils de test d’accessibilité

Outil|Description
:---------|:----------------------
axe DevTools|Extension Chrome/Firefox pour détecter automatiquement les erreurs
Lighthouse (Google)|Audit de performance et accessibilité
Pa11y, Accessibility Insights|Outils open-source pour l'intégration CI/CD
NVDA / VoiceOver|Lecteurs d’écran pour tests manuels
Color Contrast Analyzer|Vérification du contraste texte/fond
EcoIndex|outil d’analyse de la performance écologique d’un site.(RGESN)
GreenIT Analysis|Extension Chrome d’analyse Eco-Index.(RGESN)
Scaphandre|Agent qui mesure la consommation électrique d'un serveur (RGESN)
